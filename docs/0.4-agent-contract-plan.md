## 1. Why 0.4 is infrastructure, not UI

The 2026-09-14 judgment in `plugin-comparison-2026-09.md` §9 split the field: ZotLit 2.1.4 owns the human
writing and reading experience (in-text citation rendering, popover, DOCX export, reader following, template
engine), and it is actively maintained. CMDS Zotero keeps what ZotLit has no notion of — a canonical identity
index, preservation-aware imports, cross-vault navigation, and a contract that **AI agents** can call.

0.4 therefore adds no sidebars and no commands. It turns the plugin into the Zotero layer of the CMDS agentic
knowledge system: the paper-ingest pipeline in the LLM Wiki vault, the `/lint` and `/query` commands, and any
Claude Code subagent working on a paper. Everything ships as CLI + index contracts over pure modules, so that
if the plugin is later reduced to a script (the two-week kill-or-keep decision), the contract survives.

## 2. What the system measurement found

Seven parallel readers mapped every Zotero touchpoint across the wiki vault, the main vault, the
`research-pipeline` Claude plugin, the plugin's own API and competitor agent surfaces. The full map lives in the
workflow transcript; the findings that drove the design:

| # | Friction | Evidence |
| --- | --- | --- |
| 1 | Zotero identity is prose, not data. 2 of 14 paper hubs carry `zoteroSelectURI`; 8 record confirmation as a hand-typed `[!check]` callout; 3 have no `citekeyProvisional` key at all, so an unregistered paper is invisible to diagnostics. | hub frontmatter census |
| 2 | The provisional-citekey lifecycle is fully manual and never ends: register by hand, pin `extra: Citation Key` by hand, flip flags by hand. `/lint` claims to report the backlog but has no such check. | `paper-ingest.md:206`, `lint.md` |
| 3 | Page locators are impossible today. Every quote in the vault is section-only, even for papers whose PDF is in Zotero. | all atoms `(§X)` |
| 4 | The sanctioned resolve path needs Obsidian open, the CLI enabled and the plugin loaded; any failure collapses to `unavailable` and the agent hand-crafts curl. | `scripts/ingest.mjs` |
| 5 | Resolution only accepted a citekey or item key, but papers arrive as a DOI, arXiv id or title. | `index-service.ts` |
| 6 | `cites[]` and `[@citekey]` are validated nowhere; `## References` is hand-typed and already drifts. | RQ cards |
| 7 | The plugin already maps every hub/atom/raw note to its Zotero item and nothing reads it. | `.cmds-zotero/note-map.json` |

Measured facts that changed the design:

- **The documented BBT curl fallback is broken.** Plain-string `item.search` throws
  `Invalid condition 'blockStart'` on BBT 9.0.64. Tuple conditions (`[["DOI","is",x]]`) work.
- **Duplicate DOIs exist** in the live library (≥5 pairs), so DOI lookups need ambiguity handling.
- **Obsidian ships pdf.js** behind the public `loadPdfJs()` API (`lib/pdfjs/pdf.min.mjs` in the 1.14.1 bundle),
  so per-page text extraction needs no external binary. 141 of 447 index entries have a local PDF path.
- **The legacy `cmds-link-zotero` 0.1.0 was still enabled** in the main vault beside 0.3.0, both defaulting to
  the same index path; its refresh writes CSL-id-derived fake item keys. Disabled on 2026-09-14.
- **The wiki vault is a public git repo** that tracks `80. References/zotero-index.json`. The index carries local
  attachment paths; the PDF-text cache would carry full paper text.

## 3. The contract (v2)

`skills/cmds-zotero/references/cli-contract-v2.md` is the shipped reference; this is the summary.

**Envelope.** Every response carries `contract: 2`, `apiVersions: [1,2]`, `ok`, `checkedAt` and a `connection`
object (mode, obsidian, plugin, bbt, index freshness, `legacyPluginEnabled`, git coverage). The four v1 actions
keep `apiVersion: 1` and their v1 fields; only the six new actions read `apiVersion: 2`. Nothing pinned to
`apiVersion === 1` breaks.

**Actions.**

| Action | New? | Purpose |
| --- | --- | --- |
| `connection` | v1 + envelope | Pre-flight; offline probes `api.ready` directly |
| `info` | new | Index age, counts, libraries, settings, git and legacy-plugin warnings; never rebuilds |
| `refresh` | v1 + `--if-older-than` | Avoids accidental full rebuilds during fan-out |
| `resolve` | v1 + selectors | `--citekey \| --item-key --library \| --doi \| --arxiv \| --title [--year --author] \| --query`, with `matchedBy`, `ranked[]` and classified `vaultNotes` |
| `identity` | new | The hub/raw YAML fragment, S01 block, status callout, `citekeyCheck` with a pin instruction, bibliography, PDF pick |
| `cites` | new | Body **and** frontmatter citation scan, per-key verdicts, `## References` generation |
| `reconcile` | new | Classifies paper hubs against the index; `--apply` writes five allow-listed keys under a transition table |
| `diagnostics` | v1 + codes | v1 codes plus reconcile/cites/legacy/stale/git codes |
| `pdf-text` | new (live) | Per-page text via `loadPdfJs()`, content-hash cache under `.cmds-zotero/pdf-text/` |
| `locate` | new | Quote → `p.N` locator and `zotero://open-pdf?page=N`, offline over the cache |

**Identity vocabulary.** Hubs carry exactly `citekey`, `doi` and five new camelCase keys:
`citekeyProvisional`, `zoteroID`, `zoteroSelectURI`, `zoteroStatus`, `zoteroCheckedAt`.
`citekeyProvisional: true` now also means *registered under a different BBT key, pin pending*, so
`zoteroStatus: resolved` + `citekeyProvisional: true` is a valid pair.

**Honesty rules** (the reason this exists at all):

- A negative verdict from a stale index is **withheld**: `ok:false, reason: stale-index, indexAnswer: <raw verdict>`.
  `--allow-stale` opts back in. Offline and live share one freshness threshold.
- `unavailable` is never "not in Zotero". Connection failure and absence are separate fields.
- `ambiguous` never auto-picks; candidates are returned ranked.
- `zotero://open-pdf` always uses the **attachment** key from the payload, never the parent item key.
- `page` (1-based) and `pageLabel` (printed) stay distinct; `p.-` can never be emitted.

**Boundaries kept.** Zotero stays read-only over documented BBT RPCs. No SQLite, no companion add-on, no HTTP
listener, no telemetry, no template engine, no ZotLit code (AGPL). The single write into notes the plugin does
not own is `reconcile --apply`: `type: paper-hub` only, five keys only, monotonic transitions, YAML round-trip
guard, post-write verification, refused when stale / BBT unreachable / offline / legacy plugin enabled.

## 6. Decisions taken

- **Per-item pins stay the policy**; the BBT formula is not changed. The plugin models the gap
  (`citekeyProvisional` + `citekeyCurrent` + `pinInstruction`) instead of renaming anything.
- **The plugin may write into paper hubs**, but only through `reconcile --apply` with the allow-list and the
  transition table. Raw Sources stay immutable. Note bodies are never touched.
- **pdf.js inside the plugin is acceptable**: public API, read-only, guarded exactly like annotation images.
  Extended to vault-relative `--file` PDFs so provisional papers (whose PDFs live in
  `80. References/Attachments/`) also get page numbers.
- **Cut:** a generated catalog note, an MCP server, headless literature-note import, annotation export in
  wiki-quote format, UI actions, peer-vault note classification, offline `refresh`, `--quotes-file`, `--max-age`.

## 8. Approved completion supplement (2026-09-14)

The detailed [contract](agent-contract-v2/contract.md) is now durable in the repository; the installed skill reference
is generated from it by `scripts/sync-contract.mjs`. Earlier examples of numeric Zotero IDs, six-character item
keys, automatic PIN completion, and not-found/ambiguous as transport errors were incorrect and are replaced.

Additional release gates accepted during the planning review:

1. Preserve raw key presence and require agreeing identity evidence before proposing a write. History identifies
   an item but only exact current-key equality proves pinning. Empty DOI is the explicit absent sentinel, not a bad ID.
2. Recheck freshness/completeness, source content and frontmatter at apply time. Do not promise external-editor CAS
   or rollback that overwrites concurrent edits. Unknown write outcomes require read-only inspection, not replay.
3. Make read-only transitive: no implicit refresh/note-map publication, including when an old live plugin is found.
4. Validate direct API requests as well as CLI flags. Preserve legacy payload projections, enforce exit codes,
   bound/expire job state, keep completed results until acknowledged (`ackJob`) or their ten-minute TTL, and
   prevent unload resurrection.
5. Scope/hash-bind PDF caches, capture bytes before transfer, preserve warnings, and reject output exceeding the
   cache read cap. Report ignored and tracked data separately; untracking does not erase remote history.
6. Preserve existing dirty worktree/wiki changes. No commits, pushes, tags, real-plugin replacement or real-hub apply
   follow automatically from passing synthetic tests.
