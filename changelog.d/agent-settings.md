<!-- Package W1b-B agent-settings: user-visible change bullets for the 0.6.0 changelog. -->

- **`reconcile --apply` patches hand-formatted hubs line by line (R8).** Only the five allowed key lines are replaced or appended; comments, quoting, folded scalars, lists, trailing spaces, CRLF and the body stay byte for byte, so hubs that failed the old parse/stringify round-trip guard are no longer skipped. Values are quoted only when YAML would misread them (a backslash is written `\\`), and the patched text must parse back to the intended frontmatter before it is written. A block-scalar, multi-line, duplicated or quoted allowed key is skipped as `frontmatter-not-patchable`; a note that changed since the dry-run, even inside the write callback, is `changed-since-plan` with `wrote: false`, never an integrity failure. `apply.notes[]` add `replacedKeys` and `appendedKeys`.
- **Scoped scan policy for `reconcile --apply` (R8).** An unparseable note elsewhere in the vault no longer refuses the whole apply: `scan` adds `skippedDetail` (unreadable, parse-error, symlink) and `parseErrors`; a parse-error note inside `--folders`, an unreadable or symlinked entry, or a truncated scan still refuse it with the paths named; a hub whose citekey an unparseable note mentions is withheld individually with the new finding `blocked-by-parse-error`.
- **Every stored setting has a control.** New: *Citation trigger* (Bracket `[@` / At sign `[@` or a bare `@` / Off), *Excluded tags* (one per line, case-insensitive), *Heading highlight color* (None or a Zotero color) and *References sidebar follows the active note*; before, these four could only be changed in `data.json`. Keys and defaults are unchanged.
- **Clearer settings tab.** Areas in their own sections (Connection, Literature index, Citations, Literature notes, Annotations, Bibliography and references, Recently read, Connected vaults); request limits and the agent-only *References headings* sit under one collapsed *Advanced* heading. Each value is checked as you type with a message under the control, and *Save* stays blocked until the problems are fixed. On Obsidian 1.13 and later the rows come from the declarative settings API, so they appear in Obsidian's settings search.
- **Accurate References headings description.** It now says the list is read only by the agent CLI's `cites` action; the references sidebar, *Copy CSL-JSON* and *Write pandoc bibliography sidecar* export every resolved citation regardless.
- **Test connection in settings** reports Zotero being closed in words (the same message as the status bar) instead of a script error.
- **New agent action `annotations`.** A paper's annotations for digests, grouped by attachment in Zotero's reading order, with color, page and printed label, text, comment, tags and an open-pdf link; filters `--color`, `--type`, `--tag` and `--attachment`. It answers from the saved index (offline too); `--fresh` reads Zotero now and `--today` picks the one paper Zotero opened today. Older plugins answer `plugin-too-old`.
- **New agent action `citing`.** The notes that cite a paper under its current or a former citekey, with line, column and excerpt for every body citation and frontmatter citations listed apart; a citekey another item also carries is reported instead of guessed. Offline-capable.
- **`resolve --stdin`.** Up to 500 lookups in one call: one JSON selector per input line, one answer per line in the same order; a bad line gets its own `invalid-request` answer without stopping the rest.
- **Agent skill recipes.** The bundled skill explains summaries with page-checked quotes, checking suggested references against Zotero, annotation digests and finding citing notes.
