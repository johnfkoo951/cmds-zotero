- **`reconcile --apply` patches hand-formatted hubs line by line (R8).** Only the five allowed key lines are replaced or appended; comments, quoting, folded scalars, lists, trailing spaces, CRLF and the body stay byte for byte, so hubs that failed the old parse/stringify round-trip guard are no longer skipped. Values are quoted only when YAML would misread them (a backslash is written `\\`), and the patched text must parse back to the intended frontmatter before it is written. A block-scalar, multi-line, duplicated or quoted allowed key is skipped as `frontmatter-not-patchable`; a note that changed since the dry-run, even inside the write callback, is `changed-since-plan` with `wrote: false`, never an integrity failure. `apply.notes[]` add `replacedKeys` and `appendedKeys`.
- **Scoped scan policy for `reconcile --apply` (R8).** An unparseable note elsewhere in the vault no longer refuses the whole apply: `scan` adds `skippedDetail` (unreadable, parse-error, symlink) and `parseErrors`; a parse-error note inside `--folders`, an unreadable or symlinked entry, or a truncated scan still refuse it with the paths named; a hub whose citekey an unparseable note mentions is withheld individually with the new finding `blocked-by-parse-error`.
